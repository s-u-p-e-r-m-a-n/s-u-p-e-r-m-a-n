# Привет, я Сергей — Java-разработчик&#x20;

Занимаюсь серверной разработкой на Java и Spring Boot. Разрабатываю веб-приложения и отдельные сервисы, добавляю функциональность в существующие системы. Проектирую REST API, работаю с PostgreSQL, реализую бизнес-логику и настраиваю доступ к данным через Spring Security. При необходимости подключаюсь и к разработке фронтенда на React и TypeScript.

Мне интересно разбираться в том, как устроен процесс, для которого пишется программа. Кто может выполнить операцию? Что должно измениться в данных? Что произойдёт, если запрос придёт повторно или одна из систем ответит с задержкой? Такие детали влияют и на структуру кода, и на то, насколько удобно потом пользоваться приложением.

## Какие задачи я решаю

- **Разработка и развитие приложений.** Могу спроектировать новый модуль или разобраться в существующем коде и доработать его. Работаю с моделью данных, транзакциями, миграциями и тестами. Если изменение затрагивает API и клиентскую часть, могу реализовать обе стороны.
- **Интеграции и обмен данными.** Подключаю внешние сервисы по API и разрабатываю API для других систем. Разбираюсь в документации, сопоставляю данные и продумываю поведение приложения при ошибках, повторных запросах и расхождении состояний.
- **Авторизация и права доступа.** Реализую регистрацию, подтверждение учётной записи, работу с токенами и ролевой моделью. Учитываю как роль пользователя, так и его право работать с конкретными данными.
- **Автоматизация рабочих процессов.** Интересны задачи, где часть работы до сих пор выполняется вручную: сотрудники переносят данные между системами, сверяют статусы, обрабатывают заявки или рассылают уведомления. Могу взять такой сценарий от описания правил до работающей реализации.

## Публичные проекты

### [Telegram Mini App Shop](https://github.com/s-u-p-e-r-m-a-n/telegram-miniapp-shop)

Приложение для продаж в Telegram. Покупатель выбирает товары, оформляет заказ и следит за его состоянием. Менеджер работает с каталогом и остатками, обрабатывает заказы и может написать покупателю прямо из карточки заказа. В проекте связаны Java-бэкенд, два интерфейса на React, Telegram-бот и платёжный сервис.

Одна из интересных задач здесь — согласовать заказ, остатки и оплату. При оформлении сервер сам рассчитывает сумму и резервирует товар. Перед обращением к ЮKassa приложение сохраняет попытку оплаты в базе. Если ответ задержался, состояние счёта можно проверить позже. Когда срок оплаты истекает, резерв освобождается.

### [Spring Auth Service](https://github.com/s-u-p-e-r-m-a-n/spring-auth-service)

Сервис аутентификации и авторизации на Spring Boot и Spring Security. Изначально это модуль Rent Apartment App, который можно запускать и разбирать отдельно.

Здесь можно посмотреть реализацию регистрации с подтверждением по коду, ротации refresh-токенов и управления ролями. Для проверки логики есть модульные тесты, для интеграционных сценариев — PostgreSQL в Testcontainers. API доступен через Swagger UI, сервис запускается через Docker Compose.

### [Rent Apartment App](https://github.com/s-u-p-e-r-m-a-n/rent-apartment-app)

Многомодульное приложение для аренды жилья. Авторизация, логика аренды и отправка писем вынесены в отдельные сервисы. Запросы проходят через Spring Cloud Gateway, для обнаружения сервисов используется Eureka. В репозитории можно посмотреть устройство модулей, схему данных и взаимодействие между сервисами.

### [Telegram Lead Bot](https://github.com/s-u-p-e-r-m-a-n/telegram-lead-bot)

Бот для приёма заявок. Собирает данные в диалоге, сохраняет заявку в PostgreSQL и уведомляет администратора. Последние обращения и статистику можно посмотреть прямо в Telegram.
